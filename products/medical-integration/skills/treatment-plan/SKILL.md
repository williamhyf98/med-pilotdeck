# 多源诊疗方案生成

## 工作流

1. **汇总输入**：接收多来源临床数据（检验、检查、病历、影像摘要）和患者主诉。
2. **可选 RAG 增强**：当启用 `enable_rag` 时，先以主诉或关键摘要检索已批准的战创伤医学语料。
3. **生成方案**：基于汇总数据和检索证据（如有），生成结构化诊疗方案。所有生成由 PilotDeck Gateway 完成。
4. **校验输出**：方案必须通过 `clinical-workflows.v1` TREATMENT_PLAN schema 校验。

## 输出结构（9 段）

1. **病例综合摘要**：汇集所有来源的关键信息
2. **主要问题列表**：按优先级排序的临床问题
3. **风险分层与危急提示**：识别威胁生命的情况
4. **建议诊断方向**：基于证据的鉴别诊断
5. **建议检查与补充资料**：需要进一步收集的信息
6. **初步治疗与处置建议**：基于当前信息的处理方案
7. **转诊分级救治建议**：后送时机、等级和接收条件
8. **待确认项**：当前无法确定的关键问题
9. **不确定性声明**：明确模型的局限性

## 约束

- `sidecar_calls_model: false`：sidecar 只构造 prompt 和校验输出，不调用模型
- `generation_owner: pilotdeck`：所有生成由 PilotDeck Gateway 完成
- `humanReviewRequired: true`：方案必须由具备资质的医务人员复核
- `persist: false`：方案默认不持久化
- 高风险结论必须标注并给出安全升级路径
- 不为缺失数据伪造结果
