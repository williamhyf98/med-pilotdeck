# 固定模版病例报告（med-tools）

> **输出语言：简体中文。** 全文（标题与内容）一律使用简体中文撰写，**禁止用英文输出报告正文**，即使用户用其他语言提问也不例外。诊断名用 ICD-10 中文标准名（必要时括注英文）。

适用：用户要求**「按模版生成病例报告 / 出诊断与治疗方案」**的常规临床病例。材料来自用户口述病史、检查结果文字，或医学附件（检验/影像报告、伤情照片）。
不适用：战创伤六阶段救治方案 → **`med-trauma-stage-plan`**；教材知识点问答 → **`med-trauma-assist`**；单纯「这张 CT/报告是什么」解读 → **`med-medical`**。

## 报告固定模版（9 段，标题与顺序不可变）

一律使用 Markdown 三级标题，顺序如下：

```text
### 【病例综合摘要】
### 【主要问题列表】
### 【风险分层与危急提示】
### 【建议诊断方向】
### 【建议检查与补充资料】
### 【初步治疗与处置建议】
### 【转诊/分级救治建议】
### 【待确认项】
### 【不确定性声明】
```

- 缺资料的段写 **「暂不足以判断」**，不得整段删掉。
- 【不确定性声明】使用固定文案：**「本方案为 AI 辅助生成，最终诊断与用药请以主治医生判断为准。」**

## 诊断列表（写入【建议诊断方向】段）

每条诊断渲染为四级标题 `#### 【P{priority}】诊断名　·　系统分类`，按 priority 升序排列；从属诊断（因果层级）缩进挂在父诊断之下：

```text
#### 【P1】急性前壁心肌梗死　·　心血管
- **依据**：……
- **当前状态评估**：一句话说清病人现在处于什么状态
- **建议补充检查**：
    - ……
- **需警惕的并发症**：……
- **初步治疗建议**：
    - ……
```

诊断规则（沿用 med-mas 撰稿方案）：

1. **覆盖完整**：所有能从证据推出的可疑诊断都列出，不允许遗漏。
2. **优先级排序**：`priority` 数字越小越优先；`P1` 是最影响病情 / 最紧急的核心诊断。
3. **因果层级**：从属诊断（如「冠状动脉多支病变」从属「急性冠脉综合征」）缩进挂在上级诊断之下；同类合并，不要重复列同一疾病的多种描述；非核心的按系统分类排布（呼吸/消化/神经等）。
4. **诊断名严格对齐 ICD-10 标准命名**：写「急性心肌梗死」不写「心梗」；写「2型糖尿病」不写「糖尿病」；写「社区获得性肺炎」不写「肺炎」（证据支持更细分类型时应进一步细化）。单纯的检验值异常不能作为诊断名称；不得在诊断名中夹带部位坐标、检验数值、模糊限定词——这些细节放「依据」。

## 铁律

1. **输出语言：报告全部内容（含 9 段正文与诊断四步方案）必须使用简体中文**。即使用户用其他语言提问，报告正文仍用中文撰写；诊断名可用 ICD-10 中文标准名（必要时括注英文）。
2. 只依据用户提供的材料推理（用户文字、附件内容、`med_parse_medical` 返回的 report/summary），**不得编造**病史、检验值、影像所见或指南条文。
3. 区分「明确事实」「推断」「待确认」；不用「确诊为/一定是」，用「考虑/疑似/倾向于」。
4. 危急征象（如 ST 段抬高、肌钙蛋白升高、休克表现）→ 对应诊断置为 `P1`，并在【风险分层与危急提示】段重点提示。
5. 关键资料缺失或多源信息冲突 → 逐条写入【待确认项】。
6. 引用指南/文献建议时注明来源；材料中未出现的指南条文不得硬性引用，可标注为通用临床知识。

## 附件处理

- **DICOM / PDF / 检验报告等医学附件**：先调用 `mcp__med-tools__med_parse_medical`，并传 **`continuation_mode: "material"`**（本 Skill 是多步骤任务，解析只是材料准备）。把返回的 `report` / `summary` 并入材料，再按模版撰写。**不要**复述或改写整份 G9 报告；解析成功后必须继续未完成的病例报告 / HTML 等步骤。不要 `read_file` 这些二进制/医学文件自己解析。
- **普通照片（皮损/伤口等）**：主 Agent 直接查看图片，只描述可见所见，禁止虚构照片外的影像细节。
- **纯文字病例**：直接用用户叙述撰写。
