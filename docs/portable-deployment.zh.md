# 跨机器部署的路径约定

- `.cwd` 项目记录相对于 `PILOT_HOME` 保存；读取时再转换成当前机器的绝对路径。新建项目、定时任务及项目迁移使用同一约定，旧的绝对记录仍可读取。
- `webui.runtime.databasePath`、`workspacesRoot` 的相对值也以 `PILOT_HOME` 为基准。默认数据库为 `auth.db`；`~` 表示当前部署用户的主目录。
- 插件与旧版附件目录的软链接使用相对目标，随代码和数据目录一起移动后仍能使用。
- 运行过程中向模型、工具或操作系统传递绝对路径是正常的；这些路径应由当前部署目录计算，不能复制旧机器的运行环境。

已有数据可在停止本项目服务后执行以下命令（在仓库根目录执行）：

```sh
node scripts/migrate-portable-paths.mjs --dry-run
node scripts/migrate-portable-paths.mjs
```

数据不在默认 `.pilotdeck-home` 时，添加 `--pilot-home /当前机器的数据目录`。脚本会先备份到数据目录下的 `migration-backups/portable-paths-*`，再修改受管理的项目记录、配置和软链接；可重复执行。报告只包含文件位置，不输出配置密钥。`skipped` 中列出的外部目录或丢失目标需要按实际部署位置配置，脚本不会猜测它们的位置。

迁移时携带代码和 `.pilotdeck-home` 数据；在目标机器重新安装依赖、准备项目本地运行时并构建。不要复制 Mac 的 `node_modules`、Python 虚拟环境、`.runtime/node` 等平台相关二进制到 Linux。远程模型、RAG 的地址仍应按部署环境设置。

聊天记录、病例快照、迁移报告、历史工具调用和文档制作审计记录可能保留当时的绝对路径；它们属于历史内容，不做全文替换。生成文件的索引使用工作区相对路径。用户主动关联的外部目录需要一起迁移并保留相对位置，或在新部署中重新关联。
