# 安全策略与文件产物契约

本文档记录当前 PilotDeck 中普通 Agent、文档 Skill 和医学 MCP 的最小安全边界。它是实现约束和验收依据，不是允许 Agent 自由执行代码的说明。

## 1. 任务目录

每个 Agent 任务只有三个可见数据目录：

- `inbox/`：用户输入，只读。
- `scratch/`：中间文件、审计报告、渲染结果和工具长结果，可写，但不作为最终附件。
- `exports/`：最终交付文件，可写，也是最终附件的唯一根目录。

系统配置、Skill 安装目录、其他用户任务和服务管理目录不属于 Agent 工作区。

## 2. 文档 Skill 入口

普通 Agent 不能提交任意 shell、Python、Node、R 或可执行文件路径。Bash 只能调用系统注册的工作区检查命令和文档 Skill 业务子命令：

- PDF：`pdf.*`
- DOCX：`docx.*`
- PPTX：`pptx.*`
- 表格：`spreadsheets.*`
- 图示：`diagram.*`

每个入口的参数、输入根目录、输出根目录、可写能力和最大超时时间由 `documentCommandSpecs.ts` 与系统命令策略共同决定。管理员只能禁用或收窄已注册能力，不能新增任意脚本入口。

## 3. Skill 输出处理

文档 Skill 的脚本以 JSON 输出结果。Bash 适配层只读取明确的路径结果字段，例如：

- `output`
- `report` / `audit`
- `pages` / `outputs`
- `montage`

适配层只接受当前任务 `scratch/` 或 `exports/` 下已经存在的普通文件：

- 路径位于 `exports/` 时声明为 `final`。
- 路径位于 `scratch/` 时声明为 `intermediate`。
- `inbox/`、任务外路径、目录、符号链接和内部 QA 目录不会被声明为产物。
- 审计结果中的输入 `path` 不会因为字段名相同而被误认为新产物。

声明后的产物仍必须经过 `ToolRuntime` 校验。最终文件只能位于 `exports/`，中间文件只能位于 `scratch/`，路径必须是任务相对路径且文件真实存在。

## 4. 医学 MCP 输出

医学 MCP 必须在系统能力登记表中声明：

- 可读任务根目录；
- 可写任务根目录；
- 可信内网服务；
- 产物策略。

普通最终产物通过 MCP 返回的结构化 `artifacts` 字段声明，字段至少包含 `path`，可选 `role`、`mimeType` 和描述。MCP 输出路径由桥接层收敛到任务相对路径后，再经过统一产物校验。

医学服务生成在受控服务目录中的 DICOM 派生物、DeepChest 结果或 MinerU 内部材料，使用 `managed_derived` 策略。它们可以作为后续医学分析的内部材料，但不会直接作为用户最终附件展示。

未登记能力、未登记文件输出、任务外路径、符号链接逃逸和不符合产物策略的 MCP 输出直接拒绝。

## 5. 兼容策略

`FileArtifactCollector` 仍保留旧版兼容回退：

- 优先使用工具显式返回的结构化 `final` 产物；
- 没有结构化声明时，按既有兼容规则发现允许的工作区文件；
- `scratch/`、QA 目录、`.pilotdeck` 和派生内部目录不会作为最终附件；
- 新增工具和 Skill 必须使用结构化产物，不应依赖工作区 diff 推断。

## 6. 与离线部署的关系

上述契约不开放外网访问。网络请求仍必须通过系统登记的本机回环或远程功能服务地址，并接受统一网络策略校验。文档 Skill 的运行时依赖必须随离线交付包提供，禁止在任务执行期间安装依赖或下载代码。

## 7. 离线部署验收与运维

### 7.1 部署前提

- 运行包必须预置 Node、文档 Skill 运行时、Office 渲染依赖和医学插件依赖。
- 目标机不需要、也不应允许通过 `npm`、`pip`、`curl` 或其他下载工具补装依赖。
- 模型、RAG、RADAR、DeepChest、MinerU、Office Renderer 和 HTTP MCP 等服务地址只能来自系统配置或管理员登记的服务表。
- 未登记的公网域名、公网 IP、开放重定向目标和未知端口均应被拒绝。

### 7.2 安全配置备份与恢复

系统级安全配置位于 `$PILOT_HOME/system/security/`：

- `command-policy.yaml`：已注册命令能力的启用状态和收窄参数。
- `network-policy.yaml`：已登记内网服务的启用状态、主机、端口和协议。

管理员修改配置时，服务端执行 schema 校验、revision 冲突检查和原子替换。建议在升级或修改前备份这两个文件及其权限；恢复时先写回上一份有效备份，再通过管理员页面执行 reload，并确认当前 revision 和服务连通性。无效 YAML、越权命令、外网地址和过期 revision 都不能替换当前生效配置。

### 7.3 发布验收

每次离线发布至少执行：

1. TypeScript、服务端、前端和安全测试全部通过。
2. 使用两个应用用户分别创建任务，验证只能访问各自的 `inbox/`、`scratch/`、`exports/`。
3. 验证未知外网被拒绝，已登记的本机回环和远程私网功能服务可以连通。
4. 验证 `python`、`node`、`Rscript`、`bash -c`、管道、重定向和后台命令不能通过 Bash 策略。
5. 验证最终附件只来自 `exports/`，`scratch/` 中间文件、QA 文件和内部派生文件不会被交付。
6. 验证管理员保存、无效保存、外部修改、revision 冲突、reload 和恢复流程。

### 7.4 平台沙箱差异

- Linux 多用户部署优先使用 `bubblewrap`，任务命令只挂载当前任务目录，`inbox/` 只读，`scratch/` 和 `exports/` 可写。
- macOS 使用 `sandbox-exec`，应用目录和运行时只读，只向当前任务授予必要的目录权限。
- 多用户模式没有可用的 `bubblewrap` 或 `sandbox-exec` 时默认拒绝启动；只有单用户或管理员明确启用无 OS 沙箱模式时才允许降级。
- OS 沙箱是最后边界，不能替代命令注册、路径校验、网络登记和产物契约。
